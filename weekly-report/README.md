# weekly-report - 周报整理 Skill

自动解析 iBrain 项目看板中的任务完成状态，生成「总结一下」和「下周计划」章节。

## 调用方式

```
/weekly-report [周次]
```

- **周次参数**：如 `2026-24`，对应文件 `00.回顾与展望/01.周记/2026/2026-24.md`
- **默认值**：当前周（基于当前日期计算）
- **iBrain 路径**：`/home/zhuhy/workspace/projects/docs/iBrain`

## 核心流程

1. **定位文件** — 根据周次定位周报文件
2. **解析看板** — 解析 Section 1 的 checkbox 状态树
3. **分析已有** — 读取 Section 3/4 现有内容做增量判断
4. **生成内容** — 按模块分组生成总结和下周计划
5. **写入文件** — 替换对应 section，保留其他 section

## 状态判定规则

| 场景 | 判定 |
|------|------|
| 叶子节点 `[x]` | 任务已完成 |
| 父节点下全部子节点 `[x]` | 父任务完成，总结提升到父级 |
| 父节点下部分子节点 `[x]` | 父任务"部分完成"，完成的列出，未完成的入计划 |
| 叶子节点 `[ ]` | 未完成，进入下周计划候选 |
| 父节点 `[x]` 但子节点有 `[ ]` | 异常，以子节点为准 |

## 输出格式

Section 3 和 Section 4 统一使用编号层级：

```markdown
{一级模块}:
1. {二级模块}
   1. {条目1}
   2. {条目2}
      - {补充细节（可选）}
2. {另一个二级模块}
   1. ...
```

## 更新策略

- **Section 3（总结）**：全量生成——每次基于看板当前状态重新生成
- **Section 4（下周计划）**：增量合并——看板未完成任务全量对齐，外部任务保留

## 容错原则

- 可自动处理的自动处理
- 文件不存在 → 提示用户
- 看板无 checkbox → 提示跳过
- 无法确定的归属 → 标注 `⚠️ 需人工确认`
