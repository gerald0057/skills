# 通用证据规则

## 证据优先级

1. 同一故障窗口两端日志、状态转换和明确错误码。
2. 清零后固定时长的计数增量及比率。
3. 单次快照中的当前状态、pending/armed/active 字段。
4. 生命周期累计计数和历史极值。
5. 仅凭字段名称或不同版本源码作出的推测。

把结论标为“直接证据”“强推断”或“待验证假设”。日志中没有出现某字段不等于其值为零。

## 缺失分类

- `not_captured`：使用了精简命令或日志被截断。
- `compiled_out`：版本和构建信息可证明模块未编译或 release 库裁掉诊断。
- `not_applicable`：role、状态或功能确实不适用，例如 Device 无 Host CQA。
- `unavailable`：功能存在但平台/运行态明确报告 unavailable。
- `unknown_version`：无法确定版本，因此不能判断字段是否应存在。

证据不足时写“缺失原因未知”，不要把它包装为 `compiled_out`。

## 快照与计数

- `srf_debug -a` 不是原子快照，打印过程中热路径仍可能更新；小量计数差异可能来自采样时差。
- 单调累计数只说明“发生过”。用两份快照的差值判断当前速率。
- 先确认是否执行过 `--stats-clear`、重连或重新初始化，再比较计数。
- `max`、lifetime max 和当前统计窗口 max 的生命周期可能不同，必须按版本字段定义解释。
- 比率的分母必须匹配：CRC/sync 通常对 `rx_done`，duplicate 对已接收有效包，retransmit 对逻辑发送包。

## 两端对照

- Host 与 Device 的本地 `phy_time` 不共享绝对时间基准，只比较相位误差、间隔和事件关系。
- 地址、bitrate、interval、supervision、chanmap 不一致是高优先级错误。
- 一端 `rx_ok` 增长而另一端重传增长，可以说明 ACK/反向链路异常，不能简单归因于发射端未发送。
- USB 未连接可能让 Host 上层不消费数据，进而表现出 stop-and-wait duplicate；先隔离 RF 可靠性和 USB 消费路径。

## 源码可信度

日志中的固件版本是运行时权威。只有本地源码版本匹配，且构建配置/库 manifest 能对应时，源码才可作为实现权威；否则只能用于提出假设。
