# SmartRF-DebugIO

## 遵守核心约束

- 首次建档或关键字段缺失时读取 [requirements-qa.md](references/requirements-qa.md) 中与当前任务对应的最小回复包；已有已确认的环境和事件定义时，不为例行分析重复加载整份问卷。
- 准备或执行采集时读取 [dsview-cli.md](references/dsview-cli.md)；只使用与目标环境版本一致、已经验证的可执行文件和参数。
- 定义事件、配对边沿或计算耗时时读取 [timing-analysis.md](references/timing-analysis.md)。
- 任何依赖字段仍标记为 `[待填写]` 时，将该能力说明为待配置骨架，并停在依赖该字段的步骤之前。
- 不猜测 DSView CLI 名称、参数、设备 ID、采样能力、通道语义或时间边界。
- 区分 GPIO 直接观测、由 GPIO 推断的射频阶段和真实空口事件。没有硬件事件或空口参考时，不把 GPIO 边沿表述为精确的 on-air 时刻。
- 区分 elapsed time 与 CPU execution time。只有起止 GPIO 时，默认只能得到墙钟耗时；存在抢占、中断或睡眠时不得称为实际 CPU 占用时间。
- 保留原始采集文件，不覆盖输入；记录完整命令、工具版本、设备、采样配置、输出路径和异常状态。

## 执行工作流

### 1. 确认任务类型

将请求归入以下一种或多种类型：

- 生成或解释 DSView CLI 采集命令；
- 在获准的本机环境执行一次采集；
- 分析已有原始 capture、CSV、VCD 或其他已确认格式；
- 比较多个采集、统计分布或判断是否满足时序预算；
- 定位 TX、RX、中断或 CPU 处理阶段的异常。

确认输入、目标指标、输出格式，以及是否允许实际控制逻辑分析仪。只生成命令不等同于获得执行权限。

### 2. 检查输入门槛

执行采集前，至少确认：

- DSView/CLI 版本、可执行文件、分析仪型号和可识别设备；
- DUT 电平、共地方式、通道接线、空闲电平和边沿语义；
- 采样率或时间分辨率需求、触发、预触发、采集时长和输出格式；
- 输出路径不会覆盖原始数据。

执行分析前，至少确认：

- 输入文件格式可读且采集未截断、未溢出或静默丢样；
- 通道映射、信号编码、有效边沿和时间单位；
- 每个指标的开始事件、结束事件、配对规则和异常样本处理规则。

缺少门槛信息时，只询问当前动作所需的最小问题集；不要用默认值填补板级事实。

### 3. 准备并运行采集

1. 从 `dsview-cli.md` 选择与当前版本和设备匹配的已验证命令模板。
2. 先运行不接触硬件的本地版本和帮助检查；保存原始输出。把设备扫描或枚举视为硬件操作，因为具体驱动可能占用或重置 USB 接口，甚至加载易失性固件；确认授权、唯一目标设备和版本行为后再执行。
3. 展示将执行的完整命令、采集配置和输出文件，再按用户授权范围执行。
4. 不自行加入 `sudo`、安装驱动、修改 udev 规则或改变设备固件。
5. 采集完成后检查退出状态、输出文件、采集时长、通道、采样配置、触发位置以及 overflow/drop/truncation 指示。
6. 将本次环境和命令写入采集清单；不得仅保留加工后的 CSV 或统计结果。

若参考文档尚无已验证命令，停在命令准备阶段，并请求 `requirements-qa.md` 中的 DSView 最小回复包。

### 4. 提取并配对事件

1. 保留原始时间戳，另建分析副本并统一时间单位。
2. 按已确认的 idle、电平、pulse/toggle/level 编码和有效边沿提取事件。
3. 仅应用已确认的毛刺过滤阈值；记录过滤数量和规则。
4. 按包序号、额外 marker、非重叠约束或其他已确认规则配对开始与结束事件。
5. 将采集首尾未配对、缺失边沿、重复边沿、嵌套不明或同采样点顺序不明的事件标为异常，不纳入正常统计。
6. 仅在存在对应 DebugIO marker、协议日志或空口关联证据时，识别重传、CCA/backoff、ACK、CRC fail、RX timeout 等情形并按规则分组；证据不足时标为未知。

### 5. 计算与解释时序

对每项指标使用 `duration = end_timestamp - start_timestamp`，同时保留事件编号、原始时间戳和配对依据。至少报告：

- 指标的精确定义和单位；
- 样本数、有效样本数与排除原因；
- 单样本明细，或按需求提供 min/max、均值、p50、p95 等统计；
- 采样周期、时间量化限制和其他已知不确定性；
- 阈值判断及其依据；
- 该结果是直接观测、代理测量还是推断值。

不要报告高于采集分辨率所支持的精度。不同分析仪或不同采样时钟的数据未经同步与漂移校准时，不直接相减。

### 6. 输出结果

按以下顺序组织结果：

1. 结论与异常摘要；
2. 测试场景、硬件、固件和工具版本；
3. 采集命令与采集配置；
4. 通道及事件定义；
5. 时序明细与统计表；
6. 丢样、截断、未配对和过滤记录；
7. 观测边界、假设、不确定性与待确认项；
8. 原始采集文件和派生文件的位置。

无法形成可信结论时，明确说明缺少的证据以及下一次最小采集方案，不给出伪精确数值。
