# iBrain 周报格式与合并规则

## 章节范围

- 项目看板：`# 1 项目看板` 到 `# 2 支线任务完成情况`
- 本周总结：`# 3 总结一下` 到 `# 4 下周计划`
- 下周计划：`# 4 下周计划` 到 `# 5 学习了些什么`

忽略项目看板中标记为 `base` 的 fenced code block；它是显示配置，不是任务数据。不得修改第 1、2、5 节或之后的内容。

## 解析项目看板

解析 `- [x] 文本` 和 `- [ ] 文本`，用缩进建立父子关系；兼容空格和制表符缩进。每个节点至少保留文本、完成状态、子节点和层级。

状态按子节点优先解释：

- 无子节点的 `[x]` 为完成项，`[ ]` 为待办项。
- 子节点全部完成时，父任务视为完成，可在总结中提升到父级概括。
- 仅部分子节点完成时，已完成子项进入总结，未完成子项进入计划。
- 没有子节点完成时，父任务视为待办。
- 父节点标记 `[x]` 但存在未完成子节点时，以子节点为准，并标记数据不一致。

从看板标题和任务层级推断分组。带子项的顶层任务通常是二级模块，上方类似 `## 1.1 Sagitta SDK` 的标题通常是一级模块。无法可靠归属时保留任务，并标记 `⚠️ 需人工归类`。

## 生成“总结一下”

每次根据当前看板全量重建第 3 节，不对旧总结做增量拼接。

- 只包含完成或部分完成的任务；没有完成项时写 `本周暂无完成任务。`
- 优先描述结果或产出，避免复述过程；每项通常为一到两句话。
- 保留任务文本中的 Issue、Ticket 等编号。
- 部分完成任务列出已完成子项，并将仍未完成部分标记为 `（待解决）`。
- 无法确定语义或分类的内容放在所属分组末尾，并添加 `⚠️ 需人工确认`。

使用与原周报一致的 Markdown 编号层级，例如：

```markdown
# 3 总结一下

一级模块：
1. 二级模块
   1. 完成条目
   2. 另一条目
      - 必要的补充细节
```

## 合并“下周计划”

第 4 节采用增量合并：

1. 从现有计划中移除已在看板完成的对应任务。
2. 加入看板中的未完成任务，避免重复。
3. 保留无法追溯到看板的外部任务、学习计划和人工补充项。
4. 尽量合并进现有模块；无法归类时放入“其他”或标记 `⚠️ 需人工归类`。

判断任务是否对应时综合任务编号、核心名词和层级上下文，不要只依赖整句完全相等。存在多个可能匹配时保留现有计划并标记人工确认。

## 写后校验

- 第 3、4 节标题各保留一次，且第 5 节边界仍存在。
- 第 1、2、5 节及之后内容与修改前一致。
- 已完成任务不再作为普通待办重复出现。
- 外部计划和所有 `⚠️` 项未被静默删除。
