# GX Workbench 插件开发与适配

以目标宿主的实际实现为准，完成插件业务、通用打包和兼容验证。Mouse Flow、RSSI、AGC 是各自独立的 SmartRF 插件；PM VBAT 是串口采集参考，不是所有插件的固定模板。

## 先识别目标

先读 [版本识别与适配](references/version-adaptation.md)，区分运行中的宿主、开发源码和插件编译 SDK；它们不一定来自同一构建。读取适用的 `AGENTS.md`，记录：

- 宿主应用版本、可确认的 commit/tag、工作区修改及描述文件来源。
- `HostDescriptor` 的精确 backend/page API、服务版本、清单/包格式和反向策略。
- 插件 ID/版本、清单要求、生成身份、编译 SDK 与当前实际选用版本。

**不能仅凭应用版本选模板。** 已观察到应用同为 `0.1.0` 的构建经历多次接口扩展；纯核心描述和桌面原生串口描述也不同。不要用当前 SDK 加一个旧应用版本号来伪造旧宿主描述。

缺少目标描述时，从对应源码或目标产物查证；只有版本号时保留未知项，继续可独立完成的业务解析和代码准备，确需决定兼容范围时再询问。不要把源码构建结果默认为用户正在运行的安装包。

## 开发边界

- 宿主负责 Windows/Ubuntu、设备枚举与原生 I/O、资源仲裁、任务和存储。插件负责协议、采集流程、配置、分析与页面。同一字节的插件包跨平台验证，插件不直接调用 Node、Electron、系统命令或原生串口模块。
- 缺少底层能力时，先确定能否用现有通用服务表达；确需新增能力才在任务范围内扩展宿主并维护版本契约，不在核心写入业务命令。
- 安装不开始采集，打开页面不开始采集；启动/停止由明确操作触发。导航、页面刷新/关闭/崩溃不结束后台任务。页面只操作自己的页面上下文，设备访问和写入属于握手后的后台。
- 框架允许多个插件并行。只在资源冲突时显示宿主返回的设备、占用者和原因，提供显式重试；不抢占、不用全局单插件锁代替仲裁。
- 界面遵循现有 Fluent 工具风格，只放必要的配置、状态、操作和数据；不加入宣传说明、路线图或架构展示。

## 适配约束

1. 清单声明实际用到的最低接口和服务范围；权限、版本化能力要求、页面 API 分开核对。只有业务确实可继续且代码有降级分支时，能力才可设为 optional。
2. 运行时 API 是宿主实现、清单要求和**编译 SDK 实现**的交集。宿主增加 minor 不等于旧 SDK 实现了该 minor；静态通过仍要验证后台和页面各自握手。
3. `runtime.buildId`、前后台编译身份和输出清单必须由同一次构建生成。不要复制旧身份、从 HostHello 反推编译身份、硬填最终包摘要，或删除 runtime/UI 绕过失败。
4. 不靠降低版本要求、编辑宿主能力表、放宽反向策略或关闭校验掩盖缺失实现。旧 schema 只用于目标确需支持的旧功能；不能给 schema 1 塞入 schema 2 字段。
5. 已安装的同 ID/版本不可覆盖。修复后提升插件版本，重新构建和打包；运行期间不热替换，切换失败保留旧选择。通过宿主管理流程更新或回滚，不修改安装目录。
6. `dataChecked=false` 表示尚未检查现有数据。兼容评估和握手不执行迁移；数据格式变化须核对实际 schema、读写能力及迁移/回滚方案，不能删除数据来恢复“兼容”。

## 采集与记录

- 使用宿主给出的规范 deviceId、操作白名单和设备租约；配置/读取清零必须匹配独占权限。旧虚拟资源锁不能授权物理设备 I/O。
- 同一连接命令串行，超时不自动重发；超时可能已经执行副作用。停止、拔线、后台失败时结束等待并释放资源，重连后不擅自恢复采集。
- 接收、请求、日志和图表缓存保持有界；显示错误、溢出和缺失窗口，不补零。实时内存缓存不等于完整录制，旧 records 服务不能用于无限追加。
- SmartRF 累计计数/读取清零采集在首次读取及重连后建立基线，速率使用设备 `elapsed_us`；不把单窗口 B−C、C−D 标为丢包率。电压等绝对读数不套用计数基线规则。
- 原始数据不被分析结果覆盖；存在历史回放时复用解析与分析逻辑。

## 验证与交付

执行目标仓库实际提供的检查，具体命令和覆盖边界见 [开发与验证](references/development.md)。至少验证所改业务、不兼容时在 I/O 前拒绝、前后台握手、启停/资源回收和包在明确目标上的评估；涉及多版本时列出每个目标的结果。

只修改任务涉及的代码和文档。新增或改变 TypeScript 接口同步维护 TSDoc；若任务涉及 C/C++，按适用 `AGENTS.md` 核对 Doxygen 的文件/接口/参数方向/返回与成员语义。有 Doxygen 则检查生成诊断，无工具则静态核对并说明未生成验证；纯 TypeScript 不要求运行 Doxygen。SDK 文档使用原生构建入口和必要工具链/配置，不加入用户本地工具依赖。

交付说明包含插件 ID/新版本、目标宿主及描述来源、实际 API/服务协商、修复原因、执行的验证、插件包路径及回滚方式。分别报告静态评估、模拟/PTY、真实硬件、源码/安装包和 Windows/Ubuntu 原生结果；只完成交叉打包不能宣称 Windows 已验证。没有实际执行的检查保留为待验证。
