# 图形化报告规范

每个目标独立 PDF，页眉取实际 App 名称。总览、大模块及较大分支逐层展开，全部已确认分类可追溯。跨目标对比由用户另行指定。

Flash 展示总量；RAM 斜线为代码、留白为数据、点纹为预留/填充，确有 unknown 时加交叉纹理及实际数值。JSON/MD 保留全部类型。

总览分母为应用已用量，展开页为当前父模块已用量。容量使用率单列。Flash/RAM 各自按占用降序排列。

矩形面积严格按字节比例，小项可合并为其余，排名保留全部非零子项。Flash/RAM 各自按可用高度均衡分块，首个展开页仍为两资源双栏；续页只排尚未结束的资源，最多两栏，单栏居中。每栏保留面积图、排名、当前父模块分母和排名范围；非零资源不能出现空排名轴。

明细和附录使用同一字体及渲染器实际测得的块高度组合，先减少页数，再均衡留白。模块块和表格批次不跨页拆分；单块超高、内容越界或实际分页偏离计划时拒绝导出。保留全部分类，不通过删减小模块消除稀疏页。

## 两栏对齐

同一模块块内，两栏标题与说明分别放在共享行中，说明较长时共同增加行高。面积图等宽等高、顶边与底边对齐；图例和表头共用预留带，排名标题和百分比辅助线从同一水平位置开始。两栏共用 SVG 高度，实际绘制的排名末行按各自条目数自然结束，不拉大行距强求末行对齐。

总览、展开、续页和紧凑明细均使用上方面积图、下方排名。正常页和紧凑块分别使用对应的共用面积图高度；面积比例只比较当前资源、当前分母中的字节份额。单资源续页仍保留同一结构与居中规则。零占用显示等尺寸空面积框和 0 B，不绘制空排名轴。

RAM 保留已确认的组内、组间距；Flash 行距随名称换行和可用高度计算，上限保持紧凑，不将少量排名均匀拉满整栏。紧凑明细调整后重新测量和组合分页。

## RAM 区域布局

- 上方保留面积图，下方保留堆叠条形排名和百分比纵向辅助线。条形区不增加横向表格分隔线。
- 右侧数值区采用固定列和统一表头。每个模块上行加粗显示总占比、合计 KiB，下行显示代码、数据、预留/填充 KiB；真实未知类型另加一列，不能并入其他类型。
- 类别名称集中到表头，各列数字右对齐。总占比与代码列、合计与最右类别列共用右侧对齐边界；数值区与左侧条形分开，长名称换行。
- 同模块两行紧凑成组，组间留白明显大于组内间距。模块名和条形与两行组垂直居中，名称换行时增加该组高度。
- 以 480 单位宽的参考区域为例，组内基线间距约 14，普通模块步距约 33；这属于版式尺度，不是固定目标或页数。行数按实际宽度和名称长度计算，超限时均衡分配，例如 19 行可分为 7、6、6，避免 9、9、1 的孤立尾行。明细组合数量由实测高度决定。
- 总览、展开、紧凑明细和续页共用该布局。续页重复表头、父模块总量和分母，保持全量排名顺序与百分比轴刻度。预留/填充仅在显示时合并，统计 JSON/MD 仍分别保留整数 B。

## 外观

默认 A4 横向双栏、中文宋体风格、黑白线条。默认字体族 Noto Serif CJK SC；`--font` 指定已安装字体。检查实际嵌入字体，不能将 fallback 当成原字体已验证。

页眉仅 App，页脚仅页码。图表保留模块、数值、单位、占比及必要图例。非零小项不能被显示为 0；精确明细用整数 B。

正式 PDF 不出现提示词、确认/审批过程、样张标记、制作说明、呈现方式口号及泛化免责声明。保留真实范围和确有未知值。

附录保留目标、板级、版本、工具链、原生构建参数及关键哈希；不机械复制内部绝对路径、机器证据 JSON 或本地 wrapper 命令。

## 预览与验证

预览与终版共用同一 JSON、renderer、模板和完整分页计划；`--preview N` 在完成分页后截取前 N 页。按实际密度选择代表页。已确认映射/样式复用，换板级重建并核对分类变化。

自动检查父子/段/区域总量、实际绘制排名的完整性与顺序、数字文本、均衡分块、空排名轴、统计/PDF 哈希、计划页数、实测块边界、字体嵌入、文字边界与明显相交、每页页眉页脚。旧版缺少布局审计的 PDF 不能通过新版正式验收，需使用同一统计 JSON 重新渲染。

RAM 图表 audit 另核对每个模块的代码、数据、预留/填充及未知类型字节数。目视检查数值列对齐、组内/组间间距、模块与条形的垂直对应关系，并确认辅助线没有进入数值区。

共用分区审计保存从实际 SVG 读取的面积边界、排名标题及辅助线起点，并检查同块一致。实际排版另核对每个图形的顶边、底边和宽度，说明行增加时也不能造成两栏错位。回归应覆盖紧凑块、续页、零资源及不同排名数量。

再渲染全部页面，逐页检查图块、纹理、长名称、极小项、排名列对齐、分页和密度。边界检查不能证明内部没有遮挡。`--visual-reviewed` 只在看过最新页面后使用。

渲染器依赖 WeasyPrint，验证器依赖 Poppler；统计和仓库测试使用标准库。布局审计记录实际 Python/WeasyPrint 版本及脚本、模板哈希。日常生成保持已验证字体和渲染环境；更新字体、渲染器或版式后，回归真实报告及长名称、零占用、未知类别和分页临界输入，再做目视复核。自动检查不能证明所有字形均无视觉遮挡。

默认从 PATH 选择 Poppler，需要明确选择已验证运行时时可用 `--poppler-dir` 指定其可执行目录。不固化环境缓存路径、特定 Poppler 版本或字体文件路径。
