# 无线 DebugIO 时序分析参考

状态：骨架。先完成事件映射和指标定义，再据此实现解析或给出数值结论。

## 建立观测模型

为每个事件标注证据层级：

1. `observed`：逻辑分析仪直接采到的 GPIO 电平或边沿；
2. `proxy`：经固件/硬件映射验证，可代表某个无线或 CPU 阶段的 marker；
3. `inferred`：结合协议、固定偏移或外部日志推断出的事件。

报告中不得把 `proxy` 或 `inferred` 静默写成直接的空口事实。记录 GPIO 打点位置、实现方式和已知延迟；未校准时把该延迟列入不确定性。

## 事件提取与配对

1. 验证输入格式、时间单位、采样配置、通道名和采集完整性。
2. 按 idle、电平与编码规则提取边沿；不得自行选择上升沿或下降沿。
3. 只应用已确认的毛刺规则，并记录过滤前后事件数。
4. 优先使用包 ID、编码总线或公共 marker 配对；其次使用明确的非重叠测试约束。
5. 对并发、嵌套或重传场景，单根 level/toggle 信号无法唯一配对时停止推断。
6. 排除 capture 边界半事件、缺失边沿、重复边沿和顺序落在同一采样点且无法判定的样本。
7. 若 toggle 丢失一次边沿可能导致后续相位反转，检测到不一致后将受影响区间整体标为不可用。

## 分辨率与不确定性

- 记录采样率和采样周期，避免声称能分辨同一采样点内的先后顺序。
- 检查通道数对可用采样率、存储深度和 streaming 带宽的影响。
- 检查 overflow、USB 丢样、截断和触发前后缓存不足；发现后不得静默统计。
- 将 GPIO 写入延迟、ISR 延迟、MMIO/编译器排序、探头阈值和线缆差异记录为已知或待校准误差源。
- 两个不同采样时钟的数据未经共同 marker、漂移和传播延迟校准时，不直接计算跨设备时间差。

## TX、RX 与 CPU 的解释边界

- 将“TX 请求到完成”“radio 活跃时间”“单次空口帧时间”“含 CCA/backoff/retry 的总事务时间”定义为不同指标。
- 将“RX 窗口”“包接收”“CRC/IRQ 延迟”“上层处理”定义为不同指标。
- 将任务或 ISR 的 `end - start` 默认解释为 elapsed time。若期间可能抢占、睡眠或等待 DMA，只有 scheduler/ISR marker 或其他依据才能计算真实 on-CPU 时间。
