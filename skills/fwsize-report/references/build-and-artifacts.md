# 构建与产物

记录 target-id、App、Board、配置、revision/dirty、工具链、LTO 策略、实际入口和原生命令。来源优先使用仓库文档和构建清单，不固定 Make/CMake/某个 SDK 的开关。

## 构建顺序

1. 检查 clean 删除范围，将分析目录放在该范围之外。
2. 保存仍需使用的历史产物。SDK 支持时为各目标设置独立构建目录。
3. 每个目标分别 clean/build，保留日志、退出码和有效配置。
4. 成功后固定同批 ELF、MAP、最终链接布局、必要 .o/.a 或输入段属性清单，保存哈希。
5. 再开始可能清理共享目录的下一目标。

构建与分析命令由 agent 根据 SDK 执行，本 skill 不另造构建系统。使用明确参数，避免拼接未经转义的 shell 文本。

目标、配置、build-id 决定快照和报告身份。板级/配置变更必须重建；版式变更使用同一统计 JSON。保存历史结果的溯源关系。

## LTO 核验

新构建默认 clean、关闭工程 LTO，具体变量来自实际项目。用户指定发布配置或既有产物时保留其条件。

检查真实编译/链接参数及新对象中的工具链特定 LTO/IR 标记。只检查传入变量不够。预编译库单独检查；被丢弃的临时 LTO 贡献不计入占用。工程 LTO 已关闭与全部第三方库无 LTO 是不同结论。

活跃 LTO 内容导致来源丢失时保留真实未归属项，不按函数名猜源模块。

## 失败与证据

失败时保留日志、MAP、已生成对象。不得用上次残留 ELF 配本次 MAP。

容量超限记录区域、容量和超限字节。更换板级、裁剪功能或放宽链接容量仅在用户指定/已有明确授权范围执行。没有授权时保留失败结论及可完成的阶段结果。

文件变化、校验失败或物理总量冲突时暂停依赖该证据的统计，先解决输入。阶段结果准确标记其已知范围。

有 FwScope bundle 时使用正式 bundle 入口验证，不手工抽取部分成员绕过校验，不改 manifest/checksum。普通输入也需记录同批构建依据和哈希。

## 文档边界

本地封装工具用于执行/归档，SDK 原生入口用于使用说明及报告复现信息。本地工具名和内部执行细节留在构建记录中，不误写成 SDK 自带依赖。
